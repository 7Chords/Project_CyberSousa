# 存档与历史记录说明

本文档说明当前 `GamePlayerDataMgr` 的实际存档行为，便于后续配置剧情和排查分支条件。

## 1. 当前存档模型

- 当前只使用一份覆盖式存档，存储在 `PlayerPrefs` 的 `GameCore.SaveData`。
- `SaveDailyProgress(int nextDayIndex)` 每天结算或切到下一天时，都会把整份 `SaveData` 重新写回同一个 key。
- 因此现在不是“按天保留多份历史存档”，而是“单存档覆盖更新”。

## 2. 每日存档日志里各字段的含义

示例日志：

```text
[GamePlayerDataMgr] 每日存档完成：nextDayIndex=1，绩效值=70，NPC好感度数量=5，已选对话选项数量=3，送达记录数量=5
```

含义如下：

- `nextDayIndex`
  - 表示读档后将要开始的天数索引。
  - 不是“已经额外保存了一份第 N 天的独立快照”。
- `绩效值`
  - 存的是当前总绩效值。
  - 不保留每天的增减明细。
- `NPC好感度数量`
  - 表示当前存档里记录了多少个 NPC 的累计好感度。
  - 每个 NPC 只保留当前累计值，不保留每天变化过程。
- `已选对话选项数量`
  - 表示当前存档里记录了多少个“玩家曾经选过的对话选项 id”。
  - 这是历史累计集合，不是当天明细。
- `送达记录数量`
  - 表示当前存档里记录了多少个“住户曾被送到某楼层”的历史项。
  - 这是历史累计集合，不是当天明细。

## 3. 对话选项历史的记录方式

- 当前使用 `HashSet<long>` 记录玩家选过的对话选项 id。
- 记录对象是玩家实际点击的 `SELECT` 类型对话节点 id。
- 只记录“是否选过”，不记录以下信息：
  - 不记录是哪一天选的。
  - 不记录选择顺序。
  - 不记录同一个选项被重复选了几次。
- 同一个选项 id 即使多次命中，集合里也只会保留一条。

因此，当前基于对话历史的条件判断语义是：

- 某个选项“曾经选过”
- 某个选项“从未选过”

而不是：

- 第几天选过
- 最近一次选了什么
- 选过多少次

## 4. 送达历史的记录方式

- 当前使用 `customerId + floor` 组合键记录送达历史。
- 只记录“这个住户是否曾被送到这个楼层”。
- 不记录以下信息：
  - 不记录是哪一天送达的。
  - 不记录送达顺序。
  - 不记录同一组合被触发了多少次。

因此，当前基于送达历史的条件判断语义是：

- 某住户“曾被送到某楼层”
- 某住户“从未被送到某楼层”

## 5. 这些历史数据何时清空

以下情况会清空这些累计历史：

- 新开游戏时，`BeginNewGame()` 会先清除存档，再重置运行时数据。
- 游戏结束进入结局时，会清除当前存档。
- `ResetRuntimeData()` / `OnDiscard()` 也都会清空这些运行时集合。

因此，“永久”仅指“在当前这份流程存档持续存在期间会跨天累计保留”，不表示项目会长期保留按天历史档案。

## 6. 当前实现结论

当前版本支持：

- 跨天累计保存当前绩效值
- 跨天累计保存 NPC 当前好感度
- 跨天累计保存“选过哪些对话选项 id”
- 跨天累计保存“哪些住户被送到过哪些楼层”

当前版本不支持：

- 按天保存独立存档快照
- 回看“第几天选了什么”
- 回看“第几天把谁送到了哪”
- 统计某个选项被选了几次
- 统计某个送达结果发生了几次

如果后续要支持“按天回看历史”，需要单独扩展 `SaveData` 结构，不能直接复用当前这套集合式记录。

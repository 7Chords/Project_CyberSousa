# Project_CyberSousa 无限滚动列表使用与原理

## 1. 文档目标

这份文档专门讲当前项目里新增的这套无限滚动列表框架。阅读顺序按“由浅到深”组织：

1. 先看怎么用。
2. 再看接入时每个类该写什么。
3. 最后看它内部是怎么完成虚拟化、对象池、刷新和重排的。

如果只是想尽快落地一个列表，优先看第 2 到第 5 节。

---

## 2. 这套列表解决了什么问题

它是一套基于当前项目 `Node / Panel / Mono` UI 架构实现的单轴虚拟化滚动列表，主要解决：

- 数据很多时，不能把所有 item 一次性实例化出来。
- 列表 item 需要复用，避免滚动时持续创建和销毁。
- 同一个列表里需要混用多个 item prefab。
- 运行时需要替换某类 item prefab，并让当前列表立刻刷新。
- 业务层想保留类似 `OnGetItemByIndex -> NewListViewItem(prefabName)` 的接入方式。

当前实现范围：

- 支持纵向和横向。
- 支持单列纵向、单行横向。
- 支持多 prefab。
- 支持每个列表实例私有对象池。
- 支持可见项刷新、指定项刷新、数量变化、滚动定位、尺寸变化后的重排。

当前不做：

- Grid。
- 瀑布流。
- Snap。
- 自动布局驱动真实排版。

## 4. 最短使用路径

如果你要在项目里新做一个列表，推荐按下面 5 步走。

### 4.1 准备 item prefab

每个 item prefab 根节点至少需要：

- `RectTransform`
- `SCLoopListViewItem`
- 一个 `UIMonoLoopItemBase` 子类

可选但常用：

- `LayoutElement`
- `Image`
- `Text`

注意：

- item 的真实摆放由 `SCLoopListView` 控制。
- 不要依赖 `VerticalLayoutGroup / HorizontalLayoutGroup / ContentSizeFitter` 给 content 排 item。
- item 自己可以有 `LayoutElement`，当前实现会用它配合 `RectTransform.rect` 做尺寸测量。

### 4.2 给 item 写一个 Mono

示例见 `Assets/_Scripts/GameCore/UI/LoopListDemo/UIMonoLoopDemoItem.cs`。

```csharp
public class UIMonoMyListItem : UIMonoLoopItemBase
{
    public Image imgIcon;
    public Text txtTitle;
    public LayoutElement layoutElement;
}
```

这层只负责暴露组件引用。

### 4.3 给 item 写一个轻量 Panel

推荐继承 `UIPanelLoopItemBase<TMono>`。

```csharp
private sealed class UIPanelMyListItem : UIPanelLoopItemBase<UIMonoMyListItem>
{
    public void SetData(MyData data, int index)
    {
        mono.txtTitle.text = data.title;
    }

    protected override void OnRecycle()
    {
        mono.txtTitle.text = string.Empty;
    }
}
```

这层负责：

- 绑定数据。
- 处理复用前的重置。
- 如果需要，也可以在这里挂点击事件。

### 4.4 准备列表容器

当前推荐使用 `UIMonoLoopListContainer` 作为宿主容器 Mono，见：

- `Assets/_Scripts/GameCore/UI/Common/SCLoopListPanelBase.cs`

它本身继承自现有的 `UIMonoCommonContainer`，额外暴露：

- `loopListView`
- `txtTitle`
- `txtStatus`

你的页面 prefab 或运行时代码里，需要有：

- 一个 `ScrollRect`
- 一个 `Viewport`
- 一个 `Content`
- `ScrollRect` 同节点上挂 `SCLoopListView`

### 4.5 写一个列表业务 Panel

推荐直接继承：

- `UIPanelLoopListBase<TContainerMono, TItemPanel, TItemMono>`

最少只需要实现 3 个核心方法：

- `GetItemCount()`
- `GetItemPrefabName(int index)`
- `BindItem(TItemPanel panel, int index, SCLoopListViewItem item)`

示意代码：

```csharp
private sealed class MyListSectionPanel
    : UIPanelLoopListBase<UIMonoLoopListContainer, UIPanelMyListItem, UIMonoMyListItem>
{
    private readonly List<MyData> _datas;

    public MyListSectionPanel(List<MyData> datas)
    {
        _datas = datas;
    }

    protected override int GetItemCount()
    {
        return _datas.Count;
    }

    protected override string GetItemPrefabName(int index)
    {
        return _datas[index].prefabName;
    }

    protected override void BindItem(UIPanelMyListItem panel, int index, SCLoopListViewItem item)
    {
        panel.SetData(_datas[index], index);
    }
}
```

然后在页面 Panel 里：

1. 创建业务 Panel。
2. 调用 `BindContainer(containerMono)`。
3. 调用 `ReloadData()`。

## 5. 常用 API 应该怎么用

这部分是最常用的。

### 5.1 初始化列表

底层入口：

```csharp
InitListView(
    int itemTotalCount,
    Func<SCLoopListView, int, SCLoopListViewItem> onGetItemByIndex,
    SCLoopListInitParam initParam = null)
```

但在业务层一般不直接手写，通常通过 `UIPanelLoopListBase.BindContainer()` 自动触发。

### 5.2 改列表数量

```csharp
SetListItemCount(int itemCount, bool resetPos = true)
```

适合：

- 追加数据。
- 删除数据。
- 整体换数据集。

项目里的典型调用见 `UIPanelLoopListDemo.OnAppendClicked()` 和 `OnRemoveClicked()`。

### 5.3 刷新某一项

```csharp
RefreshItemByItemIndex(int itemIndex)
```

适合：

- 某个索引的数据变了。
- 只想更新一个当前可见 item。

注意：

- 只有当前正在显示的 item 才会被立刻刷新。
- 不可见项不会主动实例化出来。

### 5.4 刷新当前可见项

```csharp
RefreshAllShownItem()
```

适合：

- 可见区域内所有 item 的文案或表现一起变了。
- 不想重建整个列表。

项目里的 `Refresh Visible` 按钮就是这个作用。

### 5.5 滚到指定索引

```csharp
MovePanelToItemIndex(int itemIndex, float offset)
```

适合：

- 定位到选中的数据。
- 打开页面后跳到某个索引。

业务层封装入口是：

```csharp
ScrollToIndex(int index, float offset = 0f)
```

### 5.6 item 尺寸变化后通知列表

```csharp
OnItemSizeChanged(int itemIndex)
```

适合：

- 某个 item 展开/收起后高度变了。
- 文本撑高了 item。
- 横向卡片宽度变了。

调用后列表会：

1. 重新测量这个 item。
2. 更新后续索引的起始位置缓存。
3. 重新计算 content 尺寸。
4. 重新摆放当前可见项。

### 5.7 运行时替换某类 prefab

```csharp
OnItemPrefabChanged(string prefabName)
```

使用方式分两步：

1. 先改 `SCLoopListItemPrefabConfig.itemPrefab`
2. 再调用 `OnItemPrefabChanged(prefabName)`

项目里的示例见：

- `UIMonoLoopListDemo.SetVerticalATemplateSwapped()`
- `UIPanelLoopListDemo.OnSwapPrefabClicked()`

### 5.8 清理列表

```csharp
Clear()
```

适合页面关闭、列表销毁时调用。

业务层里 `UIPanelLoopListBase.Dispose()` 已经会帮你做这件事。

## 7. 接入时每个类该承担什么职责

这一节最重要，因为它决定后面代码会不会乱。

### 7.1 `SCLoopListView`

职责：

- 列表核心调度器。
- 计算哪些索引应该出现。
- 控制 item 创建、回收、重排。
- 管理 content 尺寸与滚动位置。

不负责：

- 业务数据来源。
- item 的业务绑定细节。
- item 点击后做什么。

### 7.2 `SCLoopListViewItem`

职责：

- 挂在 item 根节点上。
- 保存列表运行时元信息。
- 提供 `RectTransform` 和组件缓存。

关键字段：

- `ItemIndex`
- `ItemId`
- `ItemPrefabName`
- `ParentListView`
- `UserObjectData`
- `Padding`
- `StartPosOffset`

其中最关键的是：

- `UserObjectData`

当前项目里，它被用来缓存 item 对应的 `UIPanelLoopItemBase<TMono>` 逻辑对象，这样 item 复用时不需要业务层自己维护字典。

### 7.3 `SCLoopListItemPool`

职责：

- 管某一个 prefabName 对应的池。
- 预创建 item。
- 提供取出和回收。
- 支持“本帧临时回收”和“正式回收到池”。

它是每个 `SCLoopListView` 私有的，不走全局 `SCPoolMgr`。

这样做的好处是：

- 不同列表实例互不干扰。
- 列表关闭时更容易清理。
- 替换某个 prefab 时只重建当前列表里对应的池。

### 7.4 `UIMonoLoopItemBase`

职责：

- 作为 item prefab 的轻量 Mono 基类。
- 只缓存 `RectTransform`。

业务子类在这层挂所有组件引用。

### 7.5 `UIPanelLoopItemBase<TMono>`

职责：

- 作为 item 的轻量逻辑控制器。
- 负责初始化一次。
- 负责每次复用时重新绑定。
- 负责回收前重置状态。

核心方法：

- `InitializeIfNeeded`
- `Bind`
- `OnRecycleFromList`

业务覆写点：

- `OnInitialize()`
- `OnBind(...)`
- `OnRecycle()`

### 7.6 `UIMonoLoopListContainer`

职责：

- 作为列表宿主容器 Mono。
- 暴露 `SCLoopListView` 和状态文本引用。

它继承自现有 `UIMonoCommonContainer`，但语义更专门，明确是给循环列表用的。

### 7.7 `UIPanelLoopListBase<TContainerMono, TItemPanel, TItemMono>`

职责：

- 作为业务列表容器逻辑基类。
- 统一封装列表初始化、刷新、定位、换 prefab。
- 统一处理 `OnGetItemByIndex` 到 `itemPanel.Bind` 的桥接。

业务层只需要实现：

- `GetItemCount()`
- `GetItemPrefabName(int index)`
- `BindItem(...)`

这也是当前项目里最推荐直接复用的一层。

## 8. 运行链路是怎么串起来的

下面按页面打开后的真实顺序讲。

### 8.1 页面打开

`GameInitializer.startGame()`

-> `UINodeMgr.AddNode(new UINodeLoopListDemo(...))`

-> `UINodeLoopListDemo.OnEnterNode()`

-> 加载 `panel_loop_list_demo`

-> 创建 `UIPanelLoopListDemo`

-> `Initialize()`

### 8.2 Demo 页面初始化

`UIPanelLoopListDemo.AfterInitialize()`

会做这几件事：

1. `mono.EnsureBuilt()`
2. 生成纵向和横向演示数据
3. 创建两个 `LoopListDemoSectionPanel`
4. 分别 `BindContainer(...)`
5. `ReloadData(true)`

### 8.3 绑定容器时发生了什么

`UIPanelLoopListBase.BindContainer()`

里面会：

1. 记录 container mono
2. 如果列表还没初始化，就调用 `loopListView.InitListView(...)`
3. 执行 `OnBindContainer()`
4. 更新状态文本

### 8.4 `InitListView()` 做了什么

`SCLoopListView.InitListView()` 内部顺序大致是：

1. 找到 `ScrollRect / Content / Viewport`
2. 应用 `SCLoopListInitParam`
3. 保存 `onGetItemByIndex`
4. 建立尺寸缓存 `SCLoopListSizeCache`
5. 回收旧显示项
6. 重建各 prefab 对应的本地对象池
7. 根据排列方向修正 `content` 的 anchor/pivot
8. 把滚动位置设到起点
9. 计算 content 尺寸
10. 首次刷新可见项

### 8.5 首次刷新可见项

`UpdateVisibleItems(true)` 会：

1. 根据当前滚动位置算出可见范围需要哪些索引
2. 把范围外的显示项回收到临时池
3. 对范围内缺失的索引调用 `CreateItemByIndex()`
4. 新 item 创建后测量尺寸
5. 更新 content 尺寸
6. 给所有可见项重新定位
7. 把本帧临时回收项正式归还对象池

### 8.6 `CreateItemByIndex()` 如何拿到业务 item

链路是这样的：

`SCLoopListView.CreateItemByIndex(index)`

-> 调用业务传进来的 `_onGetItemByIndex`

-> 实际落到 `UIPanelLoopListBase.OnGetItemByIndex(...)`

-> 先用 `GetItemPrefabName(index)` 决定 prefab

-> 调用 `listView.NewListViewItem(prefabName)`

-> 取出 item 上的 `TItemMono`

-> 从 `item.UserObjectData` 里拿 `TItemPanel`

-> 没有就 new 一个并 `InitializeIfNeeded`

-> `itemPanel.Bind(item)`

-> 业务层 `BindItem(panel, index, item)`

所以业务层拿到的是“已经带着 Mono 引用、并且缓存好的 item panel 对象”。

## 9. 它的虚拟化原理是什么

这是这套列表最核心的部分。

### 9.1 它不是边滚边全部刷新，而是只维护可见索引区间

每一帧 `LateUpdate()` 都会尝试调用：

- `UpdateVisibleItems(false)`

它不会扫描所有数据，而是只做两件事：

1. 当前应该显示哪些索引。
2. 当前显示的 item 里，哪些该回收，哪些缺失要补出来。

这就是虚拟化的核心。

### 9.2 它怎么知道该显示哪些索引

它先拿到：

- 当前主轴滚动位置
- 视口主轴尺寸
- 预加载与回收阈值

然后得到一个“希望覆盖的主轴区间”：

- `viewStart = scrollPos - distanceForNew0`
- `viewEnd = scrollPos + viewportSize + distanceForNew1`

再通过尺寸缓存把这个区间映射成索引范围：

- `minIndex`
- `maxIndex`

有限列表时走 `SCLoopListSizeCache.GetItemIndexByPosition(...)`
无限索引模式时用默认尺寸粗略估算。

### 9.3 为什么需要尺寸缓存

因为 item 高度或宽度未必都一样。

`SCLoopListSizeCache` 维护两份信息：

- 每个索引当前的主轴尺寸
- 每个索引在 content 中的起始位置

这样一来：

- 想知道某个索引摆在哪，可以 O(1) 取起始位置。
- 想通过滚动位置反查索引，可以二分查找。

这就是它能支持“不同 item 尺寸混排”的关键。

### 9.4 为什么首屏或新出现 item 还要测一次尺寸

因为初始化时，列表只知道一个默认尺寸：

- `itemDefaultWithPaddingSize`

真实尺寸只有 item 被实例化并完成绑定后才能测出来，所以新 item 出现时会：

1. `LayoutRebuilder.ForceRebuildLayoutImmediate(rect)`
2. 读取 `rect.rect.height` 或 `rect.rect.width`
3. 加上 `item.Padding`
4. 回写给 `SCLoopListSizeCache`

如果测量结果和默认值不一样，就会触发 content 尺寸更新与 item 重排。

## 10. 对象池是怎么工作的

### 10.1 为什么不是全局池

这次没有复用 `SCPoolMgr`，而是每个 `SCLoopListView` 自己维护：

- `Dictionary<string, SCLoopListItemPool>`

原因是列表 item 有几个特殊性：

- 必须知道属于哪个列表实例。
- 必须保留 content 父节点语义。
- 可能在运行时只替换某一个 prefab。
- 页面关闭时需要整体清理。

### 10.2 一个 prefab 对应一个池

`SCLoopListItemPool` 内部维护：

- `_recycledItems`
- `_tmpRecycledItems`

其中：

- `_tmpRecycledItems` 表示这一帧刚被标记回收，但还没正式放回池。
- `_recycledItems` 表示下一次可以直接复用。

这么设计的作用是避免在同一轮更新中，刚回收的 item 又立刻被错误复用，导致链路更难推理。

### 10.3 取 item 的顺序

`GetItem()` 时会按这个顺序取：

1. `_tmpRecycledItems`
2. `_recycledItems`
3. 实在没有就 `Instantiate`

### 10.4 回收时还会做什么

`SCLoopListView.RecycleItemTmp()` 会先看：

- `item.UserObjectData is ISCLoopListItemPanel`

如果是，就先调：

- `OnRecycleFromList()`

所以 item 自己有机会清理旧状态，比如：

- 文本清空
- 图片恢复默认
- 解绑临时表现状态

## 11. 多 prefab 和运行时换 prefab 是怎么成立的

### 11.1 多 prefab

多 prefab 的前提是：

- `GetItemPrefabName(index)` 能根据业务数据返回 prefab 名

底层并不关心为什么用这个 prefab，它只认名字，然后去对应池里拿对象。

### 11.2 运行时替换 prefab

逻辑分两层：

1. 外层先修改 `SCLoopListItemPrefabConfig.itemPrefab`
2. 再调用 `SCLoopListView.OnItemPrefabChanged(prefabName)`

`OnItemPrefabChanged()` 内部会：

1. 找到该 prefabName 对应的 config
2. 回收当前所有显示项
3. 清空本帧临时回收
4. 销毁该 prefabName 对应池中的已有对象
5. 用新的 prefab 重新初始化这个池
6. 重新刷新可见项

注意这个细节：

- 它只重建目标 prefab 对应的池。
- 但为了保证显示正确，会先把当前所有 shown item 回收一次，再重新按索引拉起。

## 12. 数量变化、刷新、尺寸变化分别走哪条链路

这三个场景很容易混，所以单独拆开。

### 12.1 数量变化

入口：

- `SetListItemCount()`

做法：

1. 更新总数
2. 重建尺寸缓存
3. 回收当前显示项
4. 更新 content 尺寸
5. 重新定位到起点或直接刷新当前视图

适合：

- 数据增删
- 全量换数据

### 12.2 刷新单项或可见项

入口：

- `RefreshItemByItemIndex()`
- `RefreshAllShownItem()`

做法：

- 不改总数。
- 只把目标显示项回收并重新按当前索引创建。

适合：

- 文案变化
- 状态变化
- 图标变化

### 12.3 item 尺寸变化

入口：

- `OnItemSizeChanged()`

做法：

1. 重新测量这个索引的主轴尺寸
2. 更新它之后的所有 startPos
3. 更新 content 尺寸
4. 所有当前可见项重新摆位

适合：

- 折叠面板展开
- 动态文案撑高

这条链路比普通刷新更重，因为它会影响后续所有索引的位置。

## 13. 当前实现和现有通用容器的关系

项目里原本就有：

- `UIMonoCommonContainer`
- `UIPanelContainerBase`

这次没有硬改它们的语义，而是新增了：

- `UIMonoLoopListContainer`
- `UIPanelLoopListBase<...>`

原因很直接：

- 普通容器更像“装一组常规 item”。
- 虚拟列表需要自己接管 item 的创建、回收、重排和定位。
- 两者的生命周期和约束完全不一样。

所以当前关系可以理解为：

- `UIMonoCommonContainer` 是普通容器基底。
- `UIMonoLoopListContainer` 是循环列表专用容器。

这样做的好处是不会把老容器概念污染得过重。

## 14. 设计边界和注意事项

这部分很值得在正式业务接入前先过一遍。

### 14.1 只支持单轴

当前只支持：

- 单列纵向
- 单行横向

如果后面要做多列 Grid，不能直接在这套实现上硬堆。

### 14.2 content 不要再挂自动布局驱动真实排版

不要依赖：

- `VerticalLayoutGroup`
- `HorizontalLayoutGroup`
- `ContentSizeFitter`

原因是 item 的位置由 `SCLoopListView.SetItemPrimaryPosition()` 手动计算。

### 14.3 item 根节点必须规范

推荐 item 根节点始终满足：

- 有 `RectTransform`
- 有 `SCLoopListViewItem`
- 有具体 `UIMonoLoopItemBase` 子类

否则业务接入层在 `GetCachedComponent<TItemMono>()` 那里会直接失败。

### 14.4 无限索引模式已保留，但目前主要按有限列表验证

语义上支持：

- `itemTotalCount >= 0` 有限数据
- `itemTotalCount == -1` 无限索引源

但当前 Demo 和主要验证场景都基于有限数据。

无限模式下：

- content 总尺寸不会按有限长度更新
- 索引范围靠默认尺寸粗估

所以真正业务使用前还需要按场景单独验证。

### 14.5 列表项尺寸测量依赖当前 prefab 的实际布局结果

如果 item 内部布局比较复杂，或者绑定数据后还会异步加载内容，可能需要在内容完成后再额外调一次：

- `NotifyItemSizeChanged(index)`

## 15. 推荐的业务接入模板

这一段可以直接当 checklist 用。

### 15.1 新建 item prefab

- 根节点挂 `SCLoopListViewItem`
- 根节点挂 `UIMonoLoopItemBase` 子类
- 配好内部 UI 引用

### 15.2 新建 item Mono

- 只放组件引用

### 15.3 新建 item 逻辑 Panel

- 继承 `UIPanelLoopItemBase<TMono>`
- 写 `SetData`
- 按需覆写 `OnRecycle`

### 15.4 给宿主页面准备 `UIMonoLoopListContainer`

- 持有 `SCLoopListView`
- 持有状态文本

### 15.5 新建列表业务 Panel

- 继承 `UIPanelLoopListBase<...>`
- 实现数量、prefab 选择、绑定逻辑

### 15.6 页面打开时绑定

```csharp
_mySectionPanel = new MySectionPanel(_datas);
_mySectionPanel.BindContainer(mono.myLoopListContainer);
_mySectionPanel.ReloadData(true);
```

### 15.7 数据变化时调用对应 API

- 增删数据：`ReloadData()` 或底层 `SetListItemCount()`
- 局部刷新：`RefreshItem(index)`
- 可见项刷新：`RefreshVisibleItems()`
- 定位：`ScrollToIndex(index)`
- 换 prefab：`ReplacePrefabAndRefresh(prefabName)`
- 尺寸变化：`NotifyItemSizeChanged(index)`

## 16. 一句话总结这套架构

如果只用一句话概括：

这套无限滚动列表的思路是，用 `SCLoopListView` 处理“显示哪些 item、摆在哪里、何时回收”，用 `UIPanelLoopListBase` 处理“业务数据怎么映射到 item”，再用 `UIPanelLoopItemBase` 处理“单个 item 复用时怎么绑定和清理”。

换句话说：

- 底层只管虚拟化。
- 中层只管桥接。
- 业务层只管数据绑定。

这也是它能和当前项目 `Node / Panel / Mono` 架构比较自然融合的原因。
